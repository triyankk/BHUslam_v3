# JT16 proximity backend correction — 18 November 2026

The operator correctly pointed out that PRX1_TYPE was RangeFinder. The earlier native proximity-enable tool had incorrectly requested **4** for the JT16 transport. This was an implementation/configuration error: Jetson sends eight horizontal MAVLink DISTANCE_SENSOR packets, so the correct Cube backend is **2 (MAVLink)**. Backend 4 polls Cube rangefinder instances; with only the current downward rangefinder and the second disabled, it has no horizontal proximity source. This explains the observed PRX1 No Data despite incoming JT16 scans and outgoing companion packets.

The native C++ tool now requests PRX1_TYPE=2 for --enable-proximity-only. Its simulated-Cube test asserts a single write to 2 and preservation of unrelated values; all existing Cube integration scenarios passed in 16.37 s. The integration project's base native_avoidance.proximity_type was already 2 and was not changed.

The operator's prior JT16/BendyRuler enable request remains the intended scope. Props-off confirmation from the preceding ground test was retained. A fresh native filtered disarmed Cube readback preceded the correction. Only PRX1_TYPE changed **4 -> 2**, saved and read back, followed by the necessary disarmed reboot. No arming, mode, mission or EKF source-selection command was sent. A separate post-reboot read-only inspection verifies persistence and preservation. GPS source1 POSXY/VELXY/VELZ=3, POSZ=1, YAW=1; EK3_SRC_OPTIONS=0; VISO_TYPE=3; all scoped rangefinder, RC, notification and BendyRuler settings remain unchanged.

The mapper and existing sole Cube/JT16 owner were paused only for exclusive access and restored by a shell trap. VINS stayed warm. Recording and ten-beep cue logic were not edited. No new Python runtime or process was introduced. The existing observation relay and its profile guard remain unchanged.

Current BendyRuler tuning remains OA_TYPE=1, horizontal OA_BR_TYPE=1, lookahead 4 m and margin 1.5 m. This backend correction establishes the appropriate message receiver; it is not a field obstacle-response, direction, braking-distance or collision-avoidance validation. RC7 low continues to gate simple avoidance; BendyRuler only applies in AUTO/GUIDED/RTL. Existing minimum-altitude/ground filtering and downward-range dependencies are preserved.

Post-correction live observation: 65 one-second samples, with all 55 samples after the first ten seconds reporting Cube proximity healthy and stable; Cube stayed disarmed throughout. 3055 more proximity packets were sent during that steady interval. JT16 final scan rate 4.929 Hz; largest sampled scan age 220 ms. No steady latest STATUSTEXT reported PRX1 No Data; VisOdom unhealthy remains a separate current issue. All five services were active afterward.

Evidence: config/before.json, requested.json, after.json, changes.json, summary.json and restore.param; independent before-audit.json/after-audit.json; preservation.json; integration.log; live-health.jsonl; live-summary.json and status-final.json. The rollback value 4 is retained as historical evidence and must not be treated as the recommended transport setting.
